## 背景

- **SHIRUBE**:現場 × ポスト × シフト管理のWebアプリ(Vite + React + TS、Supabase)。現場向け(シフト・ポスト・伝票・掲示板)。警備業(交通誘導・規制保安)の会社で使う
- **SOROBAN**:SHIRUBEの経理版。**SHIRUBE本体には経理機能を混ぜず、別アプリに切り離す**。連携はAPIではなく**CSVの出し入れ**(総務の手間は許容)
- 現状、各担当がバラバラに紙 + Excelで請求書を手作業で作っていて、ミスの温床になっている。SHIRUBE側で伝票や勤務実績の整合を取り、SOROBANは「整った数字を請求書の形に出す」役割
- 将来は弥生・freeeなどの会計ソフトにCSVで渡す。決算機能は持たない
- **制約:有料サービスは使わない**(`Preferences/有料サービス不使用.md`)

**ロードマップ**:① 請求書(フェーズ1・ほぼ完成)→ ② 勤務表 → ③ 外注費チェック → ④ 経費管理

## 決定事項(ユーザーとのやり取りで確定したもの)

### 設計方針

- **SOROBANはクライアント完結**(サーバー・DBなし)。データはブラウザ内だけで処理し外部に送らない
  - マスタは画面で入力し、JSONファイルで書き出し / 読み込み(JSONファイルが正本。ブラウザの localStorage は前回の続き用)
  - 発行した請求書は PDF(ブラウザの印刷→PDF保存)+ 請求明細CSV を共有フォルダに保存して履歴とする
  - 請求書番号は `YYYYMM-元請けID(-現場ID)` で決定的に作る(DBの連番に頼らない)
  - 複数人で同時にマスタを編集する必要が出たら Supabase 等を再検討
- **技術スタックはSHIRUBEに揃える**:Vite + React + TypeScript、Vitest。金額は整数の円
- **SHIRUBEは「事実」(誰が・いつ・どこで・何時間・伝票番号)だけを出し、「お金」(単価・締め日・端数処理)はSOROBANが持つ**
- 公開は Cloudflare Pages(無料)か手元で `npm run preview`。GitHub Pages は非公開リポジトリだと有料なので使わない(未デプロイ)

### ユーザーの回答

| 質問 | 回答 |
|---|---|
| 伝票とは | 元請けにサインをもらう作業確認書。請求の根拠 |
| 料金体系 | 業者によるが基本は**人工**か**時間単価**。経費は別のことがある |
| 請求単位・締め日 | 元請けによってさまざま |
| 単価をSOROBANで持つ | 問題ない。マスタを作ってそこに入力する形がよい |
| 昼夜の単価の境目 | **元請けによる**。6:00〜20:00昼 / 20:00〜6:00夜 の所もあれば、6:00〜18:00昼 / 18:00〜6:00夜 の所もある。「夜間1名」の受注なら17:00開始でも夜間単価で請求してよい元請けもある |
| 車両・機材の台数 | SHIRUBEの伝票機能で今後記録できるようにする予定。**SOROBANでも手入力できるように、かつCSVからも取り込めるように**したい |
| 内訳書の「工事名」 | 工事名 or 現場名にする予定。**処理しやすい方を指示してくれればSHIRUBEで実装する** → `docs/shirube-csv.md` で指示済み |
| 内訳書にある別の単価列(規制保安員 単価) | 渡したものは全て元請けへの請求書。**外注費は一切関係ない**(意味は不明のまま、使わない) |
| 人工の数え方・消費税の端数処理 | 未回答 → 元請けごと / 自社設定で選べるようにした(初期値:1日=1人工、切り捨て) |

### 現行のExcel請求書(2026年8月分の見本)から分かったこと

※見本には実在の社名・住所・口座・単価が入っているため、**リポジトリには入れていない**。サンプルとテストは全て架空のデータ。

- **表紙(A4横)**:元請け名 御中、自社情報(住所・TEL・FAX・登録番号)、請求金額、表(現場名 | 仕様「規制作業一式」等 | 数量1 | 式 | 単価 | 今月請求額 | 消費税)、小計・合計、振込先、備考
- **内訳書(A4縦)**:現場ごとに1枚(同じ現場でも「作業員」など職種が違う分は別シート)。「令和8年8月分 + 現場名」、行 = 日付 | 工事名 | 時間(開始-終了)| 日勤の延べ時間 | 夜勤の延べ時間 | 車両・機材の台数 | 小計
- 計算:**延べ時間 × 時間単価**。19:00〜04:00(休憩1h)は1人あたり「日勤1h・夜勤7h」。車両・機材は台数 × 1日あたり単価
- **問題点**:表紙の消費税を行ごとに ×0.1 しているので0.5円の端数が出たり、手で上書きした数字が入ったりしていた → SOROBANでは請求書単位で1回だけ計算し、行ごとの欄は合計が一致するよう配分

## SOROBANの現状

- リポジトリ:**`cocham139/soroban`(非公開)**
- 作業ブランチ:**`claude/soroban-invoice-design-s4kaz1`**(全コミットはここ)
- `main` は初回の設計コミットの時点で作成済み。**GitHub上の既定ブランチはまだ作業ブランチのまま**(ユーザーが設定画面での切り替えに失敗したので保留中。開発に支障はない)
- **`main` へのプルリクエストはまだ作っていない**

### 主な機能

1. **実績の取り込み**:実績明細CSV・機材明細CSVをまとめて選択(ヘッダーで種類を自動判別、UTF-8 / Shift_JIS)。検証して警告(未確定・伝票番号なし・ID重複・形式不正)
   - **機材・車両の手入力**:1日ずつ / 「実績がある日すべてに追加」、数量修正・削除
2. **マスタ**:自社情報(FAX・登録番号・端数処理)、元請け(計算方式、**昼夜の分け方**、夜間帯、人工の数え方、締め日、支払日、請求単位、経費の扱い)、現場(表紙の現場名・仕様・昼夜の分け方の上書き)、人の単価(元請け × 現場 × 職種:日勤・夜勤・残業)、機材の単価(元請け × 現場 × 品目)。「まとめて追加」で未登録分を作れる
3. **請求書**:請求月を選ぶと元請けごとの締め日で集計 → 表紙 + 内訳書のプレビュー、経費・備考の手入力、印刷(表紙A4横 / 内訳書A4縦)、請求明細CSV・内訳明細CSVの出力。発行日の初期値は締め日

### 計算ルール

- **昼夜の分け方**(元請けごと、現場で上書き可)
  - 時間帯で分ける:夜間帯(元請けごと、初期値 20:00〜06:00)に入る時間を夜単価。休憩は長いほうの時間帯から引く。人工なら長いほうの時間帯の単価
  - 勤務区分に従う:勤務区分が「夜勤」なら時刻に関係なく全時間を夜単価
- 内訳書の1行 = 勤務日 + 工事名 + 開始 + 終了 が同じ隊員をまとめたもの
- 実働分を正とする(開始・終了・休憩と合わなければ警告)
- 消費税は税率ごとに請求書単位で1回だけ端数処理
