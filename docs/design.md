# SOROBAN 設計方針(フェーズ1:請求書)

## 役割

- SHIRUBE:現場の「事実」(誰が・いつ・どの現場/ポストで・何時間働いたか、伝票番号)を持つ
- SOROBAN:「お金」(単価・締め日・請求単位・端数処理・税)を持ち、整った数字を請求書の形に出す
- 連携はCSV。API連携はしない
- 決算機能は持たない。将来は弥生・freee向けの仕訳CSVを出力するアダプタを追加する

## 構成

- クライアント完結(サーバー・DBなし)。データはブラウザ内で処理し、外部に送らない
- Vite + React + TypeScript(SHIRUBEに揃える)
- CSV読み込み:自前の小さなパーサー(RFC 4180)。文字コードはブラウザ標準の TextDecoder で UTF-8 / Shift_JIS を判別
- 印刷:CSS `@media print` でA4レイアウト → ブラウザの印刷 / PDF保存
- テスト:Vitest(集計・端数処理・税計算は必ずテストを書く)
- 金額は整数の円で扱い、浮動小数点を使わない
- ホスティング:非公開リポジトリのため Cloudflare Pages(無料)またはローカル実行
  (GitHub Pages は非公開リポジトリでは有料プラン)

### 永続化

- マスタ(自社情報・元請け・単価表)は画面で入力し、JSONファイルで書き出し / 読み込み
- 前回の内容はブラウザ(localStorage)にも保持するが、正本はJSONファイル
- 発行した請求書は「請求明細CSV + PDF」を共有フォルダに保存し、それを履歴とする
- 請求書番号はDBの連番に頼らず `YYYYMM-元請けID-枝番` のように決定的に生成する
- 複数人で同時にマスタを編集する必要が出たら、Supabase等の導入を再検討する

## 入力:SHIRUBE 実績明細CSV

ファイル名:`実績明細_YYYYMM.csv`
1行 = 隊員 × 日 × 現場 × ポスト(縦持ち)

| 列 | 例 | 備考 |

| 勤務日 | 2026-10-01 | YYYY-MM-DD |
| 元請けID | C003 | 突き合わせはIDで行う |
| 元請け名 | ○○建設 | 表示用 |
| 現場ID | S015 | |
| 現場名 | △△ビル新築 | 表示用 |
| ポストID | P2 | |
| ポスト名 | 正門 | 表示用 |
| 隊員ID | E042 | |
| 隊員名 | 山田 | 表示用 |
| 勤務区分 | 日勤 / 夜勤 | |
| 開始 | 08:00 | HH:MM |
| 終了 | 17:00 | HH:MM |
| 休憩分 | 60 | 整数(分) |
| 実働分 | 480 | 整数(分)。残業を含む総実働 |
| 残業分 | 0 | 整数(分)。実働分のうち残業 |
| 深夜分 | 0 | 整数(分) |
| 休日フラグ | 0 / 1 | |
| 伝票番号 | D-1234 | 作業確認書(元請けのサイン入り)の番号 |
| 状態 | 確定 / 未確定 | |

形式のルール:

- SHIRUBEからの出力は UTF-8(BOM付き)
- SOROBANは Shift_JIS も読み込める(Excelで手直しして保存された場合に備える)
- ヘッダーは日本語で固定。SOROBAN内部で英語キーに変換する

取り込み時の検証(警告を出す):

- 状態が未確定の行
- 伝票番号が空の行
- 実績IDの重複
- マスタに単価が登録されていない元請け / 現場 / 勤務区分

## SOROBAN側のマスタ(画面で入力)

### 自社情報

社名、住所、電話、適格請求書の登録番号、振込先

### 元請けマスタ

| 項目 | 内容 |
|---|---|
| 元請けID | SHIRUBEのIDと一致させる |
| 正式名称 / 敬称 | 御中 など |
| 計算方式 | 人工 / 時間単価 |
| 締め日 | 末日 / 20日 / 15日 など(元請けごとに異なる) |
| 支払期日 | 翌月末 など |
| 請求単位 | 元請けでまとめる / 現場ごとに分ける |
| 経費の扱い | 本体の請求書に含める / 別の請求書にする |

### 単価表

元請け(×現場、任意)× 勤務区分 ごとに:

- 人工単価
- 時間単価
- 残業の時間単価
- 深夜・休日の割増(必要な元請けのみ)

現場の単価が登録されていればそれを使い、なければ元請けの単価を使う。

## 請求書

### 集計期間と支払期限

- 請求月と元請けの締め日から集計期間を決める(例:2026-10、20日締め → 2026-09-21〜2026-10-20)
- 締め日がその月にない場合(2月30日など)は末日で締める
- 支払期限は「請求月の n か月後の m 日(または末日)」

### 明細の計算

実績を「現場 × 勤務区分 × 休日かどうか」でまとめ、1グループから最大3行を作る。

| 行 | 人工・1日1人工 | 人工・按分 | 時間単価 |
|---|---|---|---|
| 基本 | 件数 × 人工単価 | 所定内実働分 ÷ 所定実働分 × 人工単価 | 所定内実働分 ÷ 60 × 時間単価 |
| 残業 | 残業分 ÷ 60 × 残業時間単価 | 同左 | 同左 |
| 深夜割増 | 深夜分 ÷ 60 × 深夜割増(0なら行を出さない) | 同左 | 同左 |

- 所定内実働分 = 実働分 − 残業分
- 休日の行は、休日単価が設定されていればそれを使う
- 単価は「元請け × 現場 × 勤務区分」を優先し、なければ「元請け × 全現場 × 勤務区分」
- 明細の金額は1円未満を四捨五入。金額は常に整数の円で扱う

### 消費税(インボイス制度)

- 税率ごとに小計を出し、消費税は請求書1枚につき税率ごとに1回だけ端数処理する
- 端数処理(切り捨て / 四捨五入 / 切り上げ)は自社情報で選ぶ。初期値は切り捨て
- 請求書に登録番号・税率ごとの対象額と消費税額を記載する

### 請求単位と経費

- 請求単位が「元請けでまとめる」なら1枚、「現場ごと」なら現場ごとに1枚
- 請求書番号:`YYYYMM-元請けID`(現場ごとなら `YYYYMM-元請けID-現場ID`)
- 経費は請求書ごとに手入力で追加する(税率 10% または 対象外)
  - 経費の扱いが「別の請求書」の元請けは、経費だけの請求書 `…-E` を作る

### 出力

- 印刷 / PDF保存(A4、1枚ずつ または すべて)
- 請求明細CSV:1行 = 請求書の明細1行(請求書番号・発行日・元請け・期間・支払期限・現場・摘要・数量・単位・単価・金額・税率)

### 警告とエラー

| 段階 | 内容 | 扱い |
|---|---|---|
| 取り込み | 列が足りない / 日付・分の形式が不正 | エラー(その行は取り込まない) |
| 取り込み | 実績IDの重複 | 注意(2件目以降は取り込まない) |
| 取り込み・請求書 | 未確定 / 伝票番号が空 | 注意(請求書には含める) |
| 請求書 | 元請け・単価が未登録、元請けIDの重複 | エラー(その実績は請求書に載らない) |
| 請求書 | 残業があるのに残業単価が0 | 注意 |

## 決定事項

- 人工の数え方は元請けごとに選べる(1日=1人工 / 実働で按分)。初期値は1日=1人工
- 消費税の端数処理は自社情報で選べる。初期値は切り捨て
