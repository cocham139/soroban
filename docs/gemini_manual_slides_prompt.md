# SOROBAN 取扱説明スライド作成プロンプト(Gemini用)

> 使い方: この下の「ここから」〜「ここまで」をそのままGeminiに貼り付けてください。
> SOROBANの実際の画面のスクリーンショットがあれば一緒にアップロードすると、画面の説明がより正確になります(実在の社名・単価・口座が写っていないサンプルデータの画面を使ってください)。

---

**ここから**

あなたは、業務アプリの取扱説明書を専門に作るプレゼンテーションデザイナーです。以下の資料をもとに、経理アプリ「SOROBAN」の**取扱説明スライド**を作ってください。

## 1. 目的と読む人

- **読む人**: 警備会社(交通誘導・規制保安)の総務・経理担当者。パソコンは使えるが、プログラミングやITの専門用語は分からない。これまではExcelで請求書を手作りしていた。
- **目的**: このスライドだけを見て、毎月の請求書発行を一人でできるようになること。
- **使われ方**: 会議で映して説明するほか、印刷して手元に置く。文字だけ読んでも、図だけ見ても分かるようにする。

## 2. デザインの指示

- **図解を中心にする**。1枚につき伝えることは1つ。文章の箇条書きだけのスライドは作らない。
- 流れは矢印つきのフロー図、対応関係は「左 → 右」の対応図、時間は帯グラフ(タイムライン)、比較は左右に並べたカード、数字は大きく、で表す。
- 画面の説明は、画面の模式図(モックアップ)を描き、押すボタンや見る場所に番号つきの吹き出しを付ける。
- 色に意味を持たせる: 緑 = 完了、黄 = 注意、赤 = エラー。SHIRUBEとSOROBANは別の色で塗り分け、全スライドで同じ色を使う。
- 配色は落ち着いた紺を基調に、アクセントはそろばんの木を思わせるオレンジ1色。背景は白に近い生成り。
- 文字は大きく(本文は24pt相当以上)、1枚あたりの文字数は少なく。専門用語(API、データベース、ブランチなど)は使わない。
- 16:9、全部で12〜16枚。日本語。各スライドに、話すときの台本(スピーカーノート)を2〜4文で付ける。
- 実在の会社名・個人名・金額は使わない。例に出す名前は「東西道路管理株式会社」「サンプル警備保障株式会社」など架空のものにする。

## 3. スライドの構成(この順番で)

1. **表紙**: 「SOROBAN 取扱説明」/ サブコピー「シフトの実績から、請求書まで。」
2. **SOROBANとは**: 「これまで(Excel手作業)」と「SOROBAN」を左右に並べた比較図
3. **役割分担**: SHIRUBE = 事実、SOROBAN = お金、の2つの箱。下に「時間を直すならSHIRUBE、単価を直すならSOROBAN」
4. **全体の流れ**: SHIRUBE →(実績明細CSV)→ SOROBAN → 請求書PDF・請求明細CSV → 共有フォルダ、のフロー図。SOROBANの下にマスタJSON(正本)を置き、双方向の矢印で「書き出す / 読み込む」
5. **毎月の6ステップ**: 番号つきの6枚のカード。どちらのアプリでやるかを色で区別
6. **SHIRUBE側の入力**: 「SHIRUBEの入力欄 → 請求書のどこに出るか」の対応図(7行)
7. **画面1 実績の取り込み**: 画面の模式図と、緑・黄・赤のメッセージの意味
8. **機材・車両の手入力**: 4手順の図
9. **画面2 マスタ**: 5つの表(自社情報・元請け・現場・人の単価・機材の単価)と、それぞれが請求書のどこに効くか
10. **元請けの設定項目**: 計算方式・昼夜の分け方・締め日・支払・請求単位・経費を、選択肢つきで図示
11. **昼夜の分け方**: 18:00〜06:00の時間軸に、19:00〜04:00の勤務を帯で描く。夜間帯(20:00〜06:00)を背景に塗り、「日勤1時間・夜勤7時間、休憩1時間は長いほう(夜)から引く」と示す。下に「時間帯で分ける」と「勤務区分に従う」の結果の違いを並べる
12. **画面3 請求書**: 表紙(A4横)と内訳書(A4縦)の用紙の模式図と、それぞれに載る内容
13. **発行のしかた**: 請求月を選ぶ → 経費・備考 → 印刷でPDFに保存 → 請求明細CSVを保存 → 共有フォルダ、のフロー図
14. **計算のルール**: 「消費税は請求書ごとに1回」「請求書番号は 請求月-元請けID」「8月分のExcel請求書と一致を確認済み」を大きな数字・言葉で
15. **困ったとき**: 赤 = 請求書に載っていない分がある、黄 = 載っているが確認、の2枚のカードと、メッセージごとの直し方の表
16. **まとめ**: 覚えるのは3つだけ(マスタを変えたら書き出す / 月が替わったら前の月のデータを消す / PDFと請求明細CSVを共有フォルダへ)

## 4. 内容の資料(ここに書いてあることだけを使う。書いていない機能や数字を作らない)

### SOROBANとは
- SHIRUBE(現場向けのシフト管理アプリ)に入っているシフトの実績から、元請けあての請求書(表紙 + 現場ごとの内訳書)を作るアプリ。
- Excelで手作業していた集計・単価の掛け算・消費税の計算を自動で行う。
- 2つのアプリは直接つながっていない。SHIRUBEで保存したCSVファイルを、SOROBANで読み込んで受け渡す。
- データはパソコンのブラウザの中だけで処理され、外部に送られない。

| | SHIRUBE(現場) | SOROBAN(経理) |
|---|---|---|
| 持っているもの | 事実: 誰が・いつ・どこで・何時間・伝票番号 | お金: 単価・締め日・支払日・端数処理 |
| 使う人 | 管理者・隊員 | 総務・経理 |
| 出すもの | 実績明細CSV | 請求書(PDF)・請求明細CSV |

### 使うファイル
| ファイル | どこから来るか | 必須 |
|---|---|---|
| 実績明細_YYYYMM.csv | SHIRUBEの管理設定「経理(SOROBAN)用CSV出力」 | 必須 |
| 機材明細_YYYYMM.csv | まだSHIRUBEからは出せない(SOROBANで手入力) | 任意 |
| マスタのJSONファイル | SOROBANの「マスタを書き出す」で保存したもの。これが正本 | 必須 |

### 毎月の6ステップ
1. 【SHIRUBE】シフトの時刻・休憩・職種・工事名・伝票番号を整える(実際の時間が予定と違った日は、シフトの時刻を直す)
2. 【SHIRUBE】管理設定 →「経理(SOROBAN)用CSV出力」→ 月を選んで「CSVを保存」(前月21日〜当月末の分が1ファイルで出る)
3. 【SOROBAN 画面1】「CSVファイルを選ぶ」で実績明細CSVを読み込む
4. 【SOROBAN 画面1】車両・機材を手入力する(ある現場だけ)
5. 【SOROBAN 画面3】請求月を選び、表紙と内訳書を確認する。経費・備考があれば入力
6. 【SOROBAN 画面3】「すべて印刷」→ PDFに保存。「請求明細CSV」も保存し、共有フォルダに置く(これが発行の履歴)

初回だけ、ステップ3のあとに画面2でマスタを登録する。先にCSVを取り込んでおくと「まとめて追加」で未登録の元請け・現場・単価の行を自動で作れる。

### SHIRUBEの入力 → 請求書のどこに出るか
| SHIRUBEの入力欄 | 請求書での使われ方 | 入れ方のルール |
|---|---|---|
| 現場の「元請け」 | 請求先 | リストから選ぶ。「㈱」と「株式会社」など表記が違うと別の元請けになる |
| 現場 | 表紙の1行、内訳書の1枚 | 元請けとの契約(業務)の単位で作る。日々の作業ごとに分けない |
| 工事名 | 内訳書の「工事名」欄 | その日の伝票に書く作業名。空なら現場名が入る |
| 職種 | 単価と内訳書を分ける単位 | 規制保安員・作業員など。職種が違う人は別のシフトにする |
| 区分(日勤/夜勤) | 昼単価か夜単価か | 受注の区分。「夜間1名」の受注なら17:00開始でも夜勤 |
| 開始・終了・休憩 | 実働 = 終了 − 開始 − 休憩 | 休憩の初期値は60分。終了が空のシフトはCSVに出ない |
| 伝票番号・伝票の写真 | 確定 / 未確定 | どちらかがあれば確定。無いと注意が出る(請求書には載る) |

### 画面1: 実績の取り込み
- 「CSVファイルを選ぶ」でCSVを読み込む。実績明細と機材明細はまとめて選べて、種類は自動で見分ける。
- メッセージの色: 緑「完了」= 取り込めた件数 / 黄「注意」= 未確定・伝票番号が空・IDの重複(未確定と伝票番号なしは請求書に載る。重複は取り込まない)/ 赤「エラー」= 日付や時刻の形がおかしい行(その行は取り込まない)
- 取り込み後、元請けごとの件数と勤務日の範囲が表で出る。
- 機材・車両の手入力: ①元請けと現場を選ぶ ②品目(例: 車両トラック)と数量を入れる。品目名はマスタの単価と同じ名前にする ③「この日に追加」または「実績がある日すべてに追加」 ④一覧で数量の修正・削除ができる
- 注意: 取り込んだ実績と手入力した機材はこのブラウザに保存され、ページを閉じても残る。月が替わったときや、CSVを出し直したときは「取り込んだデータを消す」を押してから取り込み直す。

### 画面2: マスタ
| 表 | 登録するもの | 請求書のどこに効くか |
|---|---|---|
| 自社情報 | 社名・住所・TEL・FAX・登録番号・振込先・消費税の端数処理 | 表紙の右上と振込先 |
| 元請け | 正式名称・敬称・計算方式・昼夜の分け方・締め日・支払日 など | 宛先と計算のしかた |
| 現場 | 表紙の現場名・仕様(「規制作業一式」など) | 表紙の明細行 |
| 人の単価 | 元請け × 現場 × 職種ごとの日勤・夜勤・残業の単価 | 内訳書の金額 |
| 機材・車両の単価 | 元請け × 現場 × 品目ごとの1日1台あたりの単価 | 内訳書の機材の列 |

元請けの設定項目:
| 項目 | 選べるもの | 意味 |
|---|---|---|
| ID | 文字 | SHIRUBEの元請け名と完全に同じにする |
| 計算方式 | 時間単価 / 人工 | 延べ時間 × 時間単価 か、人数 × 人工単価 か |
| 昼夜の分け方 | 時間帯で分ける / 勤務区分に従う | 時刻で昼と夜に分けるか、シフトの区分で決めるか |
| 夜間帯 | 開始〜終了(初期値 20:00〜06:00) | 「時間帯で分ける」のとき夜単価になる時間帯 |
| 人工の数え方 | 1日=1人工 / 実働で按分 | 人工のときだけ。按分は 実働 ÷ 所定実働 |
| 締め日 | 末日 / 日にちを選ぶ | 例: 20日締めなら前月21日〜当月20日 |
| 支払 | 当月 / 翌月 / 翌々月 / 3か月後 と日 | 表紙に出る支払期限 |
| 請求単位 | 元請けでまとめる / 現場ごと | 請求書を1通にまとめるか、現場ごとに分けるか |
| 経費 | 本体に含める / 別の請求書 | 経費を同じ請求書に載せるか、別に発行するか |

- 現場ごとに「昼夜の分け方」を元請けの設定から変えることもできる。
- 単価の「現場ID」を空欄にすると、その元請けの全現場に同じ単価が使われる。
- 入力したら「マスタを書き出す」でJSONファイルに保存し、共有フォルダに置く。前回の内容はブラウザにも残るが、消えることがある。消えたら「マスタを読み込む」でJSONファイルを選ぶ。

### 画面3: 請求書
- 請求月を選ぶと、元請けごとの締め日で集計した請求書が一覧に並ぶ。行を押すと表紙と内訳書が下に表示される。
- 表紙(A4横・請求書ごとに1枚): 宛先、自社情報、請求金額、現場ごとの明細(現場名・仕様・数量1式・単価・今月請求額・消費税)、小計・合計、振込先、備考
- 内訳書(A4縦・現場 × 職種ごとに1枚): 日付、工事名、時間、日勤・夜勤の数量、機材の台数、小計、合計
- 内訳書の1行 = 勤務日・工事名・開始・終了が同じ隊員をまとめたもの。
- ボタン: 請求月 / 発行日(空欄なら締め日)/ 経費を追加 / 備考 / 表示中の請求書を印刷 / すべて印刷 / 請求明細CSV / 内訳明細CSV
- PDFにするには、印刷ボタンを押してブラウザの印刷画面で「PDFに保存」を選ぶ。用紙の向きは自動で切り替わる。
- 経費と備考は請求書番号ごとにこのブラウザに保存される。

### 計算のルール
- 金額 = 数量 × 単価。
- 昼夜の分け方の例(19:00〜04:00、休憩60分、夜間帯20:00〜06:00、1人):

| 元請けの設定 | 日勤 | 夜勤 | 考え方 |
|---|---|---|---|
| 時間単価 × 時間帯で分ける | 1時間 | 7時間 | 19〜20時が昼、20〜4時が夜。休憩は長いほう(夜)から引く |
| 時間単価 × 勤務区分に従う | 0時間 | 8時間 | シフトが「夜勤」なら全部が夜単価 |
| 人工 × 時間帯で分ける | 0人工 | 1人工 | 長いほうの時間帯(夜)の人工単価 |
| 人工 × 勤務区分に従う | 0人工 | 1人工 | シフトが「夜勤」なら夜の人工単価 |

- 機材・車両 = 台数 × 1日あたりの単価。
- 消費税は請求書1通につき1回だけ計算(小計 × 10%)し、端数処理もそこで1回。表紙の各行の消費税欄は、合計が一致するように振り分けた表示用の数字。
- 請求書番号 = 請求月 - 元請けID(- 現場ID)。例: 202610-C001。何度作り直しても同じ番号になる。
- 2026年8月分の実際のExcel請求書と突き合わせて、現場ごとの金額・小計・消費税・合計が一致することを確認済み。

### 困ったとき
- 赤い「エラー」= 請求書に載っていない分がある。黄色の「注意」= 載っているが確認してほしい。

| メッセージ | 原因 | 直し方 |
|---|---|---|
| 元請けがマスタに未登録 | マスタの元請けIDとSHIRUBEの元請け名が一致していない | マスタで「まとめて追加」。表記ゆれならSHIRUBEの元請け名を直してCSVを出し直す |
| 単価が未登録のため請求書に載せていません | その元請け・現場・職種(または品目)の単価が無い | マスタの単価に追加する |
| ○行目: …のため取り込みませんでした | 日付・時刻・数字の形がおかしい | SHIRUBEで直してCSVを出し直す |
| 実績IDが重複している | 同じCSVを2回取り込んだ | そのままでよい |
| 未確定の実績があります | 伝票番号も伝票の写真も無い | SHIRUBEで伝票を登録する(そのままでも載る) |
| この請求月に請求できる実績がありません | 請求月が違う・CSV未取り込み・マスタが空 | 請求月、画面1、画面2を確認 |

### まだできないこと
| 項目 | 今の状態 | 当面のやり方 |
|---|---|---|
| 機材明細CSV | SHIRUBEから出せない | SOROBANの画面1で手入力 |
| 残業 | SHIRUBEに入力欄がなく常に0 | 終了時刻を延ばして反映する(時間単価の元請け) |
| 隊員ごとの実績 | シフト単位で全員同じ時間 | 時間が違う人は別のシフトに分ける |
| 発行の履歴 | アプリ内に残らない | PDFと請求明細CSVを共有フォルダへ |
| 公開 | していない | 社内のパソコンで起動して使う |
| 勤務表・外注費チェック・経費管理 | 未着手 | 今後の予定 |

## 5. 出力してほしいもの

1. スライド本体(Googleスライド、または編集できる形式)。図はスライド上で編集できる図形で描く
2. 各スライドのスピーカーノート(2〜4文)
3. 図に使った配色(色コード)と書体の一覧
4. 資料に書かれていなくて判断に迷った点があれば、勝手に補わず、最後に質問として列挙する
